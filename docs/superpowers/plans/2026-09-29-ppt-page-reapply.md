# 现稿整页持久重新应用

依据原方案阶段 5 的重新应用及 §6.4 每次修改可撤销，基线 a550e1b6，沿用隔离分支。

设计：首次整页暂存将已验证的单页替换 PPTX 持久保存到现有本机 PC 页面备份服务，记录可选 sourceBackup 与 reapplies。已撤销且未释放两份备份的记录可重新应用；只读核对恢复页的当前完整包及全部页序，读回原包与替换源包，再创建独立新 ChangeSet，以恢复后的 Slide ID 为目标复用原暂存流程。旧记录不变；新稿先 staged，继续经独立审查和确认 commit，之后可撤销。不依赖临时 VFS 或旧基线 ID。

约束：新字段严格有界、身份不可变；旧记录兼容但无源包不显示重做。确认前后重复核对原历史、当前包、页序和两份备份；备份缺失或释放、手工修改及未知插入结果不得重放/补建。保留源单页的 sourceSlideId、pictureTarget 和 restores 语义或明确核验后构造，不复制旧视觉审阅。两个包均纳入库存引用审计；释放操作包含两份备份，须处理部分释放后的重试，不能误计孤儿或伪造已释放。新记录独立保存原页/源页保存点、可恢复及撤销。

1. 核心：presentation-existing-page.ts、presentation-existing-page-editing.ts及相关 schema/存储/事务测试。新增 reapply_existing_presentation_page_change(change_id)，复用现有 stage/commit/undo 状态循环和写前备份机制。失败先行覆盖暂存→提交→撤销→重开→重做暂存→提交→撤销、旧记录不支持、两份备份丢失/篡改/释放、当前页/页序冲突、确认过期、插入回执丢失只读恢复、新身份和源元数据不可变、双备份释放的部分失败重试。
2. 工作台：presentation-changes.ts及控制器/卡片测试，undone源包未释放显示reapply，精确旧change ID路由，显示关联来源，新记录暂存后仍独立commit；新增源包引用参与库存审计。host-runtime.ts将新工具纳入已验证的单页作用域，如暂存实际影响两页则继续沿既有stage策略。
3. 独立整体审查，Office全套测试、类型、lint、格式/差异检查，记录进度。真实宿主与专业验收仍独立计数。

兼容/回滚：旧记录保持可读，无新依赖和新目的地；保留新增记录的恢复读取通道再回滚构建。工程验证不计真实PowerPoint完成。
