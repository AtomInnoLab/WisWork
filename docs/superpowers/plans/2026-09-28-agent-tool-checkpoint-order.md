# Agent 工具检查点顺序实施计划

依据：[设计](../specs/2026-09-28-agent-tool-checkpoint-order-design.md)。目标是修正普通与确认式工具的完成检查点顺序；非目标是自动重放跨工具 AgentRun。

## 任务 1：普通工具完成顺序

- 文件：`apps/office-addin/src/agent/use-office-agent.ts`、`apps/office-addin/tests/agent-session.test.ts`。
- 先写可控测试：普通工具执行完毕后，`tool_completed` 保存未结算时 Agent 不得继续下一轮请求；既有 `tool_pending` 在执行前完成。
- 捕获执行时 `runId`，等待完成标记后交还结果。检查点失败仍采用既有保守语义，不改变工具最终结果。
- 定向测试先红后绿；提交独立改动。

## 任务 2：确认式和悬挂工具完成顺序

- 文件同任务 1，复用其完成标记辅助逻辑。
- 先写测试：提案等待确认时只保留 `tool_pending`；确认后的完成标记未保存时下一轮请求仍不启动。原本由底层技能返回 suspension 的工具也应在最终结果后标记。
- 在 suspension 的最终 Promise 中等待完成标记，不在初始占位结果上写入完成阶段。
- 运行定向与 Office 全量测试、类型检查、构建、lint、格式检查；提交。最后做独立代码审查。

## 回滚与进度

两任务只改变客户端等待次序，不改变持久 schema 或服务端接口；可按提交逆序回滚。更新整体进度台账，保持真实宿主验收口径。

## 后续补强：完成标记保存失败时终止运行

- Agent 核心增加受限的终止错误码，接到该结果时不执行同批后续工具，也不发起下一轮模型请求。
- Office 的普通、确认式和暂停式工具均在检查点保存失败时返回终止结果；保留文档内未完成检查点，提示用户检查文档后再开启新任务。
- 用受控保存失败分别覆盖普通工具和确认式工具，并运行核心/Office 的定向与全量回归。
