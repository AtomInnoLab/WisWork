# PPT Agent：项目保留期实际执行

## 目标与边界

按原方案 §13.1，将用户明确保存的项目正文保留期与匿名审计保留期从元数据变为可验证的本机行为。复用已提交的项目归属库存、生命周期 CAS、冻结、真实 Work drain、统一删除执行器与项目锁；默认 null/null 永不自动清理。此计划仅针对单机已配对 PC，工程验证全部使用临时合成目录；不部署、不对真实用户资料试行、不声称跨进程或断电事务。

保留期不能由生命周期 `createdAt` 或策略更新的 `updatedAt` 单独推断项目内容最近活动。任何活动证明、目录身份、时钟、策略版本、前台工作状态或共享归属有疑点时跳过本次自动动作并留下有限的匿名状态；不得为完成率而删除。项目已进入 deleting 的同一持久意图只允许按原回执恢复，不另起意图。永久 ID 墓碑必须保留，不能为清审计而恢复写权限。

## 架构与接线

PC 在默认关闭的治理功能内以有限频率枚举已有且真实绑定的本机项目；独立保留期服务先判断固定版本策略和独占内容活动证明，到期时调用统一删除事务的内部 retention 理由入口。外部七操作白名单和用户明确删除路径不扩展理由字段。活动证明只服务保留期内部决策，不进入预览、匿名审计或 Relay 响应；UI 在自动行为实际验证之前继续明确显示“保存策略不会自动清理”。

涉及文件：`apps/shell/src/main/presentation-project-inventory.ts`（复用现有安全步行，附加内部活动证据）；`apps/shell/src/main/presentation-project-deletion.ts`（内部 retention reason 复用冻结执行）；新增 `apps/shell/src/main/presentation-project-retention.ts`（枚举、资格、同一意图、定时入口）；`apps/shell/src/main/presentation-project-work.ts`（只读实际在途工作观察）；`apps/shell/src/main/index.ts`（仅在治理双开关实际启用后调度）；`packages/project-store/src/presentation-lifecycle.ts`（到期审计的兼容记录/不可复活锚点）；`packages/project-store/src/presentation-project-governance.ts`（纯浏览器兼容解析）；Office 卡片文字及对应测试。各文件的修改必须按下列单元顺序实施，不能以单纯 timer 或文件 mtime 快速替代归属证明。

### 单元一：可复核的内容活动证据

在现有 32768 文件、32 GiB、16 层库存预算内观察七个已证明独占的项目内容命名空间。活动时间取受验证文件/目录元数据的保守上界（至少 mtime、ctime 与创建时间），并把策略最近一次明确保存时间作为最早生效基线；共享资料活动可推迟到期，不能让其它项目的旧时间提前到期。用真实 `projects/presentations` 绑定验证发现范围，符号链接、替换、异常时间或未知资源跳过。接口返回内部活动时间、原 scope 与无法决定的有限原因；不导出文件路径、内容摘要或正文。

先用两个同文档项目、研究/交付/页面/偏好/评论/观察的真实生产写入构造 RED：旧项目刚写仍不得到期，显式策略刚保存仍不得立即到期，mtime 倒拨不能缩短等待。补目录替换、预算、未知命名空间及钩子竞态，再实现证明并 GREEN。该单元只读、可独立审查和提交，不触发删除。

### 单元二：真实到期与同一事务

新增 `createPresentationProjectRetentionService({userDataPath, acquireProjectLock, now})` 的可手动调用一次 `tick()`，由 PC `index.ts` 在 PC 端治理开关明确启用时安排定时调用；测试使用注入的确定性时钟，不依赖等待真实天数。`tick()` 枚举已绑定项目，固定原 lifecycle revision/policy 与活动证明，在共用锁和事件循环无等待段核“没有登记在途工作”，再由内部执行器持久开始 `reason:'retention'`。冻结后锁外取消并等待真实任务、锁内复查归属和原意图、执行逐资源回执。每次 partial、共享、未知或失败与用户明确删除一样保留项目正文，并只按同一 deletionId 继续。客户端无法把 `reason` 注入七操作输入。

先 RED 验证默认 null、未到期、策略变更、同时写入、排队页面备份、主锁争用、两个 tick、两个 Service、时钟倒拨、共享和执行中断；再实现最小调度及回执恢复。即使功能开关开启，不能用普通控制记录更新时间冒充内容活动；`tick()` 前后身份必须固定。完成该单元且通过跨层测试后，Office 才可更新“保留期会自动执行”的文案，并把具体到期语义解释给用户。单元独立审查、提交，不触碰真实资料。

### 单元三：匿名审计到期与最小墓碑

现有 v1 生命周期把完整审计链和 revision 一一对应；直接删事件会破坏校验。先设计向后兼容的 v2 控制记录及浏览器解析：保留 revision、状态、策略、最小永久项目 ID 墓碑、删除意图必要回执与匿名序号锚点；可按 auditRetentionDays 移除已到期的历史事件，同时保留最近事件、状态连续性与最小禁止复活证据。旧 v1 仍可读、写时显式迁移，不依赖已删除的项目正文。匿名导出只给实际留存事件与保留元数据，不能泄露路径、正文、原 URL、文档/项目真实 ID。

先 RED：v1 活跃/删除中/已删迁移，保留期 null，精确边界，部分失败回执继续，断点与篡改、重新打开不能复活旧 ID；GREEN 后独立审查和提交。任何无法安全迁移的历史记录保留而不清理，报告有限失败。完成后运行 ProjectStore、Shell、Office、Relay 的相关全量及类型/静态门禁。

## 发布、回退与进度

新定时行为受 PC 端默认关闭开关保护；Office 的独立默认关闭开关只控制用户界面，PC 不推断该构建配置。工程测试仅用合成目录。回退只关闭自动调度，不删除意图/隔离区/控制墓碑，旧运行中的原意图仍按现有只读/显式恢复规则处理。真实 Office、Windows/Mac/Web、专业任务及用户明确启用安排另行验证；目前整体严格 64% 不因计划或局部测试改变。
