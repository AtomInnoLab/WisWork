# PPT 阶段语义映射与时间线聚合

## 目标与架构

执行原方案 §7.1/7.2 与 O1：研究、规划、视觉方向、素材、逐页制作、宿主导入、页面审查、内容证据、修改及保存点操作显示对应阶段；同阶段细粒度操作默认折叠，仍可查看内部工具明细。进度来自已有 ACP 工具事件，项目完成、视觉通过和证据核验仍以持久领域回执为准，不能把工具结束伪造为 `project.completed`。

共享阶段映射由 `packages/agent-harness/src/acp-events.ts` 提供。插件根据本会话有界时间线生成纯展示分组；只聚合相邻且同阶段的工具事件，用户、助手、错误和确认事件保持因果顺序。不新建持久日志或修改恢复/宿主写入接口。

约束：原方案不回改；同文档会话隔离保持；未知工具保留通用文案，不套用未证实阶段；工具正文、参数、结果 JSON 或堆栈不进入展示。工具失败和进行中计数可见，内部调用默认折叠，确认动作永远独立可用。组中“已结束”只指工具事件，不能称页已完成。Word/Excel 保持现有工具展示。

## 交付单元 A：共享阶段映射

文件：`packages/agent-harness/src/acp-events.ts`、`src/index.ts`、`tests/acp-presentation-activity.test.ts`，必要时插件工具注册覆盖测试。

核对实际注册工具及动态名字数组，不只扫描显式 name 属性。补齐研究、视觉方向、素材、基线、交付和恢复等命名族，保留已有阶段键；导出阶段标签获取函数供展示复用。每类代表操作及重要变更/导入/恢复工具先失败测试，再实施最小映射；未知名称不误分类。执行 harness 全套与类型检查，限定文件提交。

## 交付单元 B：Taskpane 阶段聚合

文件：新增 `apps/office-addin/src/agent/presentation-stage-timeline.ts`、对应测试；`App.tsx` 接通分组与原生 details；组件测试验证默认折叠、更新计数、失败可见及确认动作独立，必要时最小样式调整。

只聚合连续同阶段工具，单个工具也用相同阶段视图；组键沿用首个事件身份；事件更新后重算，不重复创建步骤，不改已有有界事件数组。不同阶段或未知工具及用户/助手/错误/提案将分组断开。显示工具进行中、已结束、未完成数及下一步提示；详情里显示有界工具名与状态，不显示结果正文。主时间线的全部非工具内容保持原样。

先写纯投影及组件交互 RED，再实施 GREEN。核对旧组件断言的产品含义，不把流水布局断言当约束。执行 Office 全套、harness 全套、相关类型检查、定向 lint/格式、生产构建和独立完整审查。

## 回滚与验收边界

仅新增内部展示投影及兼容阶段分类键，不迁移文档/PC 持久格式，不新增数据传输或权限。按单元提交可独立回滚；沿用现有灰度设置，不直接发布。此交付完善阶段语义及聚合，不替代持久研究/规划语义事件、完整 ACP 会话续传、专业来源审核和真实 PowerPoint 面板验收；进度台账按实际证据记录。
