# 真实计划与样式接受决定的持久链路

依据原方案 §7.1、§7.3 与 O1。接受动作是工作台上的可选用户决定，不作为普通制作门禁；不从保存、编译或工具返回推断批准。

1. 测试先行：PC 存储接受具体计划修订/完整摘要与样式摘要，保存决定身份和时间；幂等、重开、文档隔离、过期/冲突拒绝及有界历史。
2. PC 新增独立接受操作，严格字段与 CAS 校验；状态返回只含决定元数据的历史，损坏记录不阻断项目读取。既有保存和制作路径保持不批准。
3. 实际插件控制器计算当前计划摘要，提交用户决定，严格核对回执；刷新/重开从实际历史恢复匹配接受状态。变化、取消、文档切换、迟到及未知写入结果不采用错误决定，不自动重提。
4. 当前计划工作台提供可选“接受当前计划与样式”，显示版本及时间，接受期间/当前已接受/历史不可读时禁用；旧 PC 不展示不支持动作。时间线生成真实 plan.approved/style.approved，历史不迁移到新计划或事实/QA。
5. 验证真实 PC 到插件重开、实际按钮、时间线、容量与安全边界，完整相关回归、类型/静态检查及构建；更新原方案严格进度。
