# PPT Agent：持久图片素材与紧凑生成引用

基线 e6fd680；继续执行已批准方案 O2。沿用隔离分支、高保障流程和既有附件传输。

## 本轮闭环

上传 PNG/JPEG → PC 校验原始摘要、格式和尺寸 → 原生解码并规范为 PNG → 文档隔离缓存 → Agent 获取素材元数据 → SlideIR 用 attachmentId 引用 → PC 编译前读取缓存 → PptxGenJS 生成图片对象。

本轮不增加远程下载、GIF/WebP/SVG、OCR 或视觉质量核验。优先解决图片字节挤占模型工具请求和重复上传问题。

## 契约

- PresentationAsset 保留现有内联形式，并增加严格引用形式 `{id,attachmentId}`。attachmentId 为原始图片 SHA-256。工具/schema 接受引用；底层编译器拒绝尚未解析的引用，由 PC 服务提供受文档隔离保护的图片。
- 原始图片最多 10 MiB、8192×8192 边长内且总像素不超过 1600 万；解码前校验头部尺寸，解码后比对实际尺寸；规范 PNG 最多 4 MiB。
- 复用附件分块协议。ready 图片元数据包括 kind=image、mime=image/png、width、height、assetSha256。文本附件保持原协议。
- 新 attachment_asset 操作从校验后的缓存返回内联资产，仅供 PC 编译解析使用；Agent 不需要接收 base64。来源保留 attachment:<原始摘要>。
- 独立协商 presentation-assets.v1；旧 PC/Relay 下图片继续走现有会话附件路径，不能误启用引用编译。文档附件能力不受影响。
- 生成请求和重试回执保存紧凑引用；PC 按同一 documentId 解析素材，验证缓存摘要。单次编译解析后的图片字节合计最多 8 MiB，生成结果仍受现有 10 MiB 上限约束。

## 实施与验收

1. 后端独立单元：原生图片校验/规范化、缓存、图片元数据、附件原件与缓存摘要、重启复用和隔离测试。
2. 共享契约与插件独立单元：引用 schema、编译器拒绝未解析引用、图片上传入口与状态、素材清单和 Agent 提示、旧版本兼容测试。
3. 主集成：PC 编译解析素材、能力协商、真实图片生成/解包与 Electron 解码验证。
4. 独立审查；全仓测试、类型检查、变更 lint、Relay 测试和两端生产构建；阶段小结。

原件与规范缓存均不接受任意路径或 URL。资料解析/图片解码不能被标记为来源已核验或视觉 QA 完成。保留分支，不自动部署。
