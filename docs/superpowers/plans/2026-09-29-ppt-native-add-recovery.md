# 原生 SlideIR 添加的持久保存点与恢复

原方案 O3 的“每个写入有回执、失败不留下半页”，以及 O5 的变更历史/撤销。当前完整新建继续 PC PptxGenJS→原生包导入；本计划限定现有 add_slide_ir_objects 支持的文字、形状、表格原位添加。

## 实际缺口与复用边界

powerpoint-skill.ts 当前直接添加仅提案内快照、executeDeclarative 与回读，重开没有对应持久 pending。现有 existing_batch 有 CAS、receiptQueue、saveWithHistory、cursor、PC 原页备份与历史；优先扩展这一契约。当前最多 8 个 batch 操作，而 SlideIR 最多 32 个含来源脚注，因此须先决定版本化的单页添加操作表达及容量预留，不能静默截断或提高所有旧记录的上限。chart change 有预先已知 after-package digest，direct add 没有，禁止冒充 chart 记录。整页恢复可复用既有原页备份恢复 stage/inspect/commit；不能暗中用整页替换代替原位添加。

## 实施顺序

1. 明确持久操作语义与边界。添加前记录原页身份/顺序、完整备份摘要、已存在对象、拟添加对象名称和受支持语义；添加中的实际身份与回读进度有显式持久状态。旧 batch 保持兼容，每个读取者都必须识别新操作或明确拒绝，不允许 unknown switch 落入其它修改分支。
2. 接入文档存储与统一历史。严格 schema、状态转移、CAS、写后读取核对及预算预留；不能 evict 未决写入，成功回执丢失可只补记录。先用新记录/旧记录/越界/状态冲突的真实持久测试定义行为。
3. 接入提案确认与原页备份。确认前复核文档、目标页、顺序和重名；原页上传并读验及 pending 成功后才调用宿主。备份或记录失败零宿主写入。不支持持久恢复的旧能力应写前明确拒绝，不能静默执行无记录添加。
4. 实现有界执行与只读恢复核对。不能一次写完整页之后假称已有逐项回执；只认领已通过语义和完整保留对象核对的结果。未写、已写、部分写、未知各有明确状态。用户编辑、重名、页序变化或复杂对象不可比时禁止自动重放。中断/取消不得抹除原备份和 pending。
5. 接通已有工作台/历史/恢复入口与确认撤销。保留原始页面可恢复，恢复使用现有受控原页包流程并明确目标；不以删除新增 shape 的简易逆操作承诺完整格式恢复。撤销/回执丢失也需可重开核对。
6. 集成故障证明、独立审查与完整相关回归。备份失败、pending 保存失败、第 N 个对象后故障、ACK 丢失、重开、用户冲突、损坏备份、撤销中断、文档隔离、容量及旧记录兼容。源码验证后构建并记录实际版本，真实 PowerPoint 编辑和保存重开仍独立待验。

不改变原方案的主路由、用户确认门禁或严格进度口径；开发与本机备份已获用户授权，不需再次请求同一授权。
