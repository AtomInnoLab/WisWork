# 宿主修改保存点的持久事件时间与回放

依据原方案 §7.1、§7.2 和写入可恢复要求，复用现有文档修改历史，不新增独立保存点系统。

1. 测试先行：新的修改保存点首次持久保存记录时间；撤销未完成不记录恢复，实际完成回执记录恢复时间，重开保持身份。
2. 在统一回执写入处生成时间，单调且不可随刷新或后续操作改变。旧记录不补造创建时间，实际旧记录撤销可记录恢复时间。
3. 严格验证日期及时间顺序；恢复时间只在实际完成回执写入时生成，重新应用后保留历史首次恢复时间。元数据使用独立有界额度，旧版满容量内容仍可恢复。保持原内容额度和 64 条上限。
4. 修改控制器传递真实记录，工作台折叠展示 checkpoint.created/restored；恢复回执不代表当前宿主或 QA 通过。
5. 验证容量、旧记录、持久重开、损坏、实际组件、全部相关回归、类型/静态检查及构建，更新严格进度。
