# WisWork LaTeX Verified Agent 设计

日期：2026-08-12
状态：已批准，进入实现
基线：`main@3408aee`

## 1. 产品目标

把现有“AI 对话 + 整文件修改提案”升级为一个可验证的 LaTeX 任务闭环：用户从正在编辑的源码或编译问题发起目标，Agent 在明确上下文中分析和提出修改，系统在隔离副本中验证提案，用户审阅后才写入正式项目，并可整体撤销。

产品赌注是：LaTeX 用户真正需要的不是更多文本生成，而是减少在多文件依赖、编译诊断和结果核对之间往返的负担。Agent 适合承担这个工作，因为它需要综合项目上下文、生成跨文件修改、调用编译器观察证据，并根据结果交付可审阅成果；单次补全或确定性脚本无法覆盖这些判断环节。

## 2. 本期用户工作流

1. 用户在编辑器选中源码，或从编译诊断发起 AI 任务。
2. AI composer 展示当前文件、选区和诊断上下文标签；用户可移除不希望发送的上下文。
3. Agent 执行项目读取、搜索、诊断读取、提案生成等动作，任务时间线实时显示动作、状态和结果。
4. Agent 创建修改提案后，主进程使用提案内容创建隔离编译输入并运行 Tectonic。正式项目文件不发生变化。
5. 审阅界面按文件和变更块展示修改原因、源码 diff 和隔离验证结果。
6. 用户明确确认后，沿用现有一次性 proposal ID、基线哈希、事务快照和原子写入机制应用修改。
7. 正式项目再次编译。用户可从任务结果撤销整次写入。

## 3. 设计边界

### 自动允许

- 读取和搜索 AI 可访问的项目文本。
- 读取结构化编译诊断。
- 在受控编译临时目录中应用提案文本并编译。
- 展示计划、工具执行过程和验证结果。

### 必须确认

- 把任何提案内容写入正式项目。
- 正式创建新文本文件。

### 明确禁止

- 删除或覆盖二进制文件。
- 执行任意 shell 命令、启用 shell escape、改变 Tectonic 参数或下载源。
- 访问项目根目录外路径。
- 把隔离验证结果当作正式应用授权。
- 编译失败后自动写入正式项目。

## 4. 架构

Renderer 负责采集用户可见上下文、呈现任务时间线、diff 和验证证据。它不能构造任意编译目录或直接写文件。

主进程的 `ProjectSession` 继续拥有项目、提案和编译授权。新增“验证提案”IPC：根据主进程已经登记的 proposal ID 取得受信提案，把 afterText 作为受限 overlay 交给编译内核。验证使用独立请求和缓存产物，不登记为正式 PDF 预览，也不消费一次性提案。

`@wiswork/latex-compiler` 在现有安全复制工作区中支持受限文本 overlay。路径必须经过相同的项目内规范化，文件数和总字节数受限，overlay 只能替换隔离 input 目录中已经存在的普通文本文件，且不改变用户项目。包含新文件的提案仍可审阅，但本期明确标记为“无法隔离验证”；原因是跨平台 Node 缺少绑定稳定父目录的 `openat` 创建原语，禁止创建比在极端目录替换竞态下冒险产生外部空文件更符合源项目零副作用边界。

## 5. 关键数据模型

### AgentContext

- `activeFile`: 当前文件相对路径。
- `selection`: 可选，包含行范围和有界文本。
- `diagnostic`: 可选，包含文件、行列、严重级别和有界消息。

上下文被序列化为清晰的用户消息附件，项目内容仍被视为不可信数据而非指令。

### TaskTimelineEntry

- `id`
- `kind`: context / read / search / compile / propose / verify / result / error
- `label`
- `state`: running / success / error / cancelled
- `detail`（有界、可展开）

首版时间线在当前会话内持久存在；聊天历史仍沿用现有项目目录聊天存储。长期任务账本留到后续版本，避免本期扩张项目存储 schema。

### ProposalVerification

- proposal ID
- success / failure
- diagnostics（有界）
- log 摘要（有界）
- 验证时间

验证结果只证明该提案在当时基线的隔离副本中可编译；正式应用后仍必须再次编译。

## 6. 失败与恢复

- 编辑缓冲区未保存：验证拒绝开始，提示用户保存或等待自动保存。
- 提案过期或基线改变：验证和应用均拒绝，要求重新生成提案。
- overlay 路径、体积非法或目标是新文件：编译进程启动前拒绝；新文件提案显示为无法隔离验证。
- 隔离编译失败：保留提案供审阅，明确展示诊断，不自动应用。
- 正式应用后的编译与隔离结果不同：展示差异并提供撤销。
- Agent 被停止：时间线标记取消，未确认提案不写入。

## 7. 安全与回滚

- proposal ID 仍为一次性正式写入授权；验证不得消费该 ID。
- 验证 overlay 只来源于 `ProjectSession` 内已经校验并持有的提案，不接受 renderer 直接传文本。
- 正式写入继续依赖基线哈希、项目事务锁、快照和原子替换。
- 代码回滚可整体回退本功能提交；数据层没有迁移。未消费 proposal 保持现有过期清理语义。

## 8. 验收标准

- 用户选择源码后，AI 面板出现可移除的选区上下文标签，发送内容包含有界行号与文本。
- 点击诊断可把该诊断带入 AI composer，而不是只能跳转源码。
- 每次工具调用在时间线显示开始与完成/失败状态。
- 提案审阅前自动执行一次隔离验证；验证期间项目文件哈希不变化。
- 非法 overlay 路径、符号链接逃逸、超限文本和新文件目标在 Tectonic 启动前被拒绝。
- 验证失败不会写入正式项目；确认应用仍只发生一次并可整体撤销。
- LaTeX、latex-project、latex-compiler 测试和 typecheck 全部通过。
