# WisWork LaTeX AI Native 编辑器设计

日期：2026-08-05
状态：已批准
目标分支：`feature/wiswork-latex`
基线分支：`feature/wiswork-integration`（待前置 PR 合并后变基到 `main`）

## 1. 目标

为 WisWork 增加一个与 Docs、Sheets、Slides、PDF 并列的本地 LaTeX 工作区。用户可以新建或导入多文件 LaTeX 项目，在源码与 PDF 之间实时编辑、编译和定位，并让现有 WisWork Agent 在项目范围内分析、提出跨文件修改、经用户确认后写入和验证。

成功标准：

- 可以新建空白或基础模板项目，也可以导入本地目录或 ZIP。
- 可以浏览和编辑项目内的文本文件，选择主 `.tex` 文件，并通过本地 Tectonic 生成 PDF。
- 编译错误能关联到文件和行；源码与 PDF 支持 SyncTeX 正向、反向定位。
- AI 可以读取、搜索和分析项目，生成多文件 Diff；只有用户明确确认后才能写入。
- 每次 AI 写入前创建一致性快照，写入后自动编译，用户可以一键撤销整次修改。
- Tectonic、项目文件和模型凭证均不越过既有 Electron 主进程信任边界。

## 2. MVP 范围

包含：

- 本地单用户项目。
- 新建项目、导入文件夹、导入 ZIP、打开最近项目。
- 文件树、文本标签页、LaTeX 语法编辑、搜索替换、诊断跳转。
- Tectonic 本地编译、PDF 预览、SyncTeX 定位、编译取消与超时。
- AI 项目问答、错误解释、多文件修改提案、确认写入、编译验证和撤销。
- 项目级主文件、编译设置和 UI 状态持久化。

不包含：

- 云同步、分享链接、多人实时协作、评论和审阅工作流。
- Git UI、在线模板市场、远程编译或任意 TeX Live 命令链。
- 自定义 shell 命令、shell escape、用户传入任意 Tectonic 参数。
- AI 自动删除文件、覆盖二进制文件或未经确认修改源码。
- WisUsage 计费；模型继续使用现有 WisModel 接入。

## 3. 方案选择

### 已选：独立 LaTeX 应用与受控本地编译服务

新增 `apps/latex`，以项目目录而不是单一 Office 文件作为文档边界。Electron 主进程负责文件访问、导入、快照、编译进程和 AI 工具；renderer 只展示文件树、源码、Diff、PDF 和诊断。

新增两个可测试的共享包：

- `packages/latex-project`：项目模型、路径策略、主文件识别、安全导入、快照和补丁事务。
- `packages/latex-compiler`：Tectonic 发现与安装、资源包校验、编译队列、进程控制、日志与 SyncTeX 结果。

该方案保留 Shell 的多应用结构，并能为目录级权限、编译进程和 AI 写入建立清晰边界。

### 未选：把 LaTeX 嵌入 Docs

Docs 以单文档编辑和 OOXML 导入导出为核心。复用它会迫使目录、多文件引用、编译产物和主文件状态进入不匹配的数据模型，后续维护成本高于新增独立应用。

### 未选：浏览器或服务端远程编译

远程编译便于统一环境，但会上传用户项目、引入服务可用性和计费依赖，与本期本地、隐私优先的范围冲突。未来协作版可在保持本地项目协议不变的前提下增加远程执行器。

## 4. 用户工作流

### 4.1 新建项目

1. 用户从 Home 或菜单选择“新建 LaTeX 项目”。
2. 选择空白项目或基础文章模板，并指定本地目录。
3. WisWork 原子创建项目文件和项目元数据，打开 `main.tex`。
4. 第一次编译时，如果资源包尚未安装，展示来源、版本和体积并开始校验下载；编辑不被阻塞。
5. 下载完成后立即编译并打开 PDF 预览。

### 4.2 导入项目

- 导入文件夹时不复制用户目录，先扫描边界和候选主文件，再由用户确认打开。
- 导入 ZIP 时解压到用户选择的新目录；先在临时目录完成安全检查，成功后原子移动。
- 主文件识别顺序为：WisWork 配置、`Tectonic.toml` 明确输入、根目录 `main.tex`、唯一包含 `\\documentclass` 的 `.tex`、用户选择。
- 识别结果写入项目元数据，但不改写用户的 TeX 源码。

### 4.3 AI 修改

1. 用户描述目标，Agent 可以列目录、搜索和读取项目内允许的文本文件，并读取最近一次编译诊断。
2. Agent 生成一个包含基线文件哈希、修改说明和多文件统一 Diff 的提案。
3. UI 展示每个文件的差异；用户可以整批确认、取消，或取消选择单个文件。
4. 主进程再次校验基线哈希。若文件已变化，则拒绝旧提案并要求重新生成。
5. 写入前创建快照，随后以临时文件加原子替换方式提交整批文本修改。
6. 提交后自动编译；错误会返回 Agent 供解释，但不会触发第二次自动写入。
7. 用户可一键撤销到写入前快照，撤销后重新编译。

## 5. 界面与状态

LaTeX 工作区采用四区布局：

- 左侧：项目树、主文件标记、新建/重命名/导入资源。
- 中间：多标签文本编辑器，支持 LaTeX 语法、搜索、行列定位和诊断标记。
- 右侧：PDF 预览、页码、缩放、SyncTeX 定位。
- 底部或可折叠面板：编译状态、结构化诊断、原始日志和 AI 对话/Diff。

renderer 状态分为编辑缓冲区、磁盘版本、已编译版本三层。自动保存采用短延迟去抖；编译只消费已经成功写入磁盘的版本。关闭标签或应用时，Shell 沿用 dirty-close 保护，并额外提示正在进行的导入、AI 写入或编译任务。

源码编辑器采用 CodeMirror 6：按扩展组合行号、历史、搜索、括号匹配、补全和诊断；LaTeX 语法先使用受维护的语言扩展，若其能力或许可证不满足要求，再以 CodeMirror 的 `LanguageSupport` 接口封装仓库内解析器。编译诊断转换为 CodeMirror lint diagnostics，不在 renderer 重复解析原始日志。CodeMirror 官方文档确认其扩展化编辑状态和诊断接口适合这一集成方式：[System Guide](https://codemirror.net/docs/guide/)、[Lint Example](https://codemirror.net/examples/lint/)。

## 6. 项目格式与存储

项目源码保持普通目录，可脱离 WisWork 使用。项目级元数据优先存放在应用 userData 的索引中，以规范化项目真实路径为键，避免默认向用户仓库加入私有文件。若未来需要可移植配置，可显式导出 `.wiswork/latex-project.json`。

最小元数据：

- schema version；
- 项目真实路径与展示名称；
- 主文件相对路径；
- 最近打开文件和布局状态；
- 固定的编译器、资源包版本；
- 最近成功编译产物和诊断摘要；
- 快照索引。

编译产物与快照放在 userData 下按项目 ID 隔离的缓存目录，不默认生成到源码树。项目移动后可通过目录内文件指纹重新关联，无法唯一关联时按新项目处理。

## 7. Tectonic 生命周期

### 7.1 可执行文件

- 每个平台打包固定版本的 Tectonic sidecar，并记录来源、许可证与 SHA-256。
- 打包流程验证目标架构；macOS arm64 构建只能包含 arm64 sidecar。
- 主进程使用应用资源内的绝对路径执行，不搜索用户 `PATH`，也不接受 renderer 指定可执行文件。

### 7.2 首次资源包下载

采用用户批准的推荐方案：安装包不内置完整 TeX 资源包。第一次需要编译时，从固定 HTTPS 地址下载固定版本 bundle 到临时文件，校验预置 SHA-256 后原子安装到 userData。下载支持取消、重试和断点恢复；校验失败的内容立即隔离且绝不执行。

编译显式指定本地 bundle，并启用 `--only-cached`，因此完成初始化后不会因文档引用新包而隐式联网。升级资源包需要新的应用清单和用户可见的下载动作，不能静默切换“latest”。Tectonic 官方 CLI 支持本地 bundle、仅缓存模式、SyncTeX 和不可信输入模式：[V1 CLI](https://tectonic-typesetting.github.io/book/latest/ref/v1cli.html)、[Tectonic.toml](https://tectonic-typesetting.github.io/book/latest/ref/tectonic-toml.html)。

### 7.3 编译调度

- 编译前把经过校验的项目文件复制到该项目专属的临时工作区；拒绝链接和越界路径，只复制允许的普通文件。Tectonic 在隔离副本内运行，不直接把用户源码目录作为工作目录。
- 使用参数数组调用子进程，不经过 shell。
- 强制 `--untrusted`、`--only-cached`、`--synctex`、指定 bundle 和独立输出目录。
- 环境变量使用最小允许列表，并额外设置 `TECTONIC_UNTRUSTED_MODE=1` 作为纵深保护。官方文档也建议在不可信内容场景使用该环境变量：[Tectonic build](https://tectonic-typesetting.github.io/book/latest/v2cli/build.html)。
- 每个项目最多一个活动编译；新请求取消过时请求，同一磁盘版本的重复请求合并。
- 设置总超时、无输出超时、输出字节上限和完整进程树终止。
- 仅把经过路径验证的主文件相对路径传给编译器。
- 编译完成后只接收预期的 PDF、SyncTeX 和日志产物；结果再映射回原项目相对路径，工作区随后清理。

## 8. AI 权限与事务边界

AI 工具分为：

- 自动允许的只读工具：列目录、搜索文本、读取允许的文本文件、读取结构化诊断、读取项目设置、请求编译。
- 必须确认的写工具：应用已有 Diff 提案、创建文本文件、重命名文本文件。
- MVP 禁止的工具：删除文件、覆盖二进制文件、执行命令、修改项目外路径、修改编译器或资源包。

即使 renderer 或模型生成了恶意路径，主进程仍必须执行相同的项目根目录、真实路径、文件类型、大小和哈希校验。确认授权绑定到规范化 Diff、基线哈希和一次性 proposal ID；修改内容变化后旧授权失效。

AI 自动编译属于受限的派生操作，不等同于授权新的写入。编译失败后 Agent 可以解释和提出下一版 Diff，但必须再次获得用户确认。

## 9. 文件与导入安全

- 所有相对路径规范化后必须仍位于项目真实根目录内；拒绝绝对路径、NUL、保留设备名和路径穿越。
- 默认拒绝跟随符号链接；已存在项目中的链接在树中标记为不可编辑，也不交给 AI 读取。
- 编译始终使用校验后的隔离副本，防止 TeX 内部文件解析绕过 renderer 和 IPC 的路径检查。
- ZIP 拒绝符号链接、硬链接、设备节点和重名覆盖，并限制压缩包大小、条目数、单文件大小、总解压大小、目录深度和压缩比。
- ZIP 先解压到新建临时目录，逐条校验并使用排他创建；全部成功后才移动到目标目录。
- 文本编辑设置单文件大小上限和 UTF-8 检查；超限或二进制文件只能作为项目资源显示。
- PDF、图片、字体等二进制文件只能由用户导入或替换，AI 不获得写权限。

`--untrusted` 是编译器级保护而不是完整 OS 沙箱。应用仍需限制进程参数、环境、工作目录、输入路径、资源消耗和网络行为，不能把 Tectonic 当作任意不可信代码的绝对隔离边界。

## 10. IPC 与信任边界

preload 暴露窄化 typed IPC：

- 项目：创建、选择目录/ZIP、打开、列树、读取/保存文本、重命名、新建。
- 编译：获取安装状态、下载资源、开始、取消、订阅状态、读取 PDF/SyncTeX/诊断。
- AI：发送请求、读取提案、确认一次性提案、撤销快照。

主进程验证 sender、窗口所属项目、request ID、schema、字符串与集合上限。renderer 不能传入任意根目录、可执行文件、bundle URL、请求头、环境变量或命令参数。PDF 通过受控 app protocol 或字节 IPC 提供，不向 renderer 暴露任意 `file://` 读取能力。

## 11. Shell 与现有能力集成

- Shell 标签类型增加 `latex`，并复用现有 WebContentsView 生命周期、最近文件和关闭保护。
- Home 快捷入口增加“新建 LaTeX 项目”和“导入 LaTeX 项目”；最近项目按目录身份展示。
- LaTeX 应用复用 `@wiswork/agent-core` 和 WisModel provider，但定义独立的项目工具集。
- PDF 渲染复用现有 `pdfjs-dist` 依赖与交互模式；若组件当前与 PDF 应用耦合，则抽取最小共享 viewer 包，而不是嵌入整个 PDF 应用。
- 项目目录与单文件 Office 文档语义不同，不强行塞入现有 file-to-project 映射；通过适配器让 project-store 记录 LaTeX 项目和聊天关联。

## 12. 错误恢复

- 资源下载失败：保留编辑能力，显示可重试状态，不留下被信任的半包。
- 编译取消或超时：终止进程树，保留上次成功 PDF，并明确标记预览已过期。
- 主文件丢失：停止自动编译，要求重新选择，不猜测写回。
- 外部修改：通过 watcher 检测；无本地未保存内容时刷新，有冲突时提供磁盘版与编辑版对比。
- AI 基线冲突：整批拒绝写入，不应用部分文件。
- AI 写入中断：依靠临时文件、事务日志和快照恢复到修改前一致状态。
- 快照空间超限：按项目配额清理最旧的非固定快照；当前操作的回滚点不可在事务完成前清理。

## 13. 测试与验收

单元测试：

- 主文件识别、路径规范化、symlink 逃逸和项目身份。
- ZIP traversal、zip bomb 限制、重复条目与原子导入。
- bundle 清单、哈希校验、失败清理和版本切换。
- 编译参数白名单、队列合并、取消、超时、诊断解析和 SyncTeX 映射。
- AI proposal 授权、基线冲突、多文件原子提交、快照与撤销。

集成/E2E：

- 新建项目、首次资源下载、离线再次编译。
- 导入目录和 ZIP、选择主文件、多标签保存与外部修改冲突。
- 成功编译、错误跳转、PDF 刷新和正反向 SyncTeX。
- AI 只读分析、Diff 确认、自动编译、失败解释和一键撤销。
- renderer 不能越权读取项目外文件、覆盖 bundle、传入命令参数或绕过确认。
- Shell 新建、最近项目、标签恢复和 dirty-close。

发布验证：

- lint、format、typecheck、unit、E2E 和 `build:all` 全部通过。
- macOS arm64 安装包验证 Electron、现有 xlsx sidecar 与 Tectonic sidecar 架构。
- Windows/Linux 在纳入发布矩阵时分别验证 sidecar、路径规则和进程终止。
- 许可证/NOTICE 包含编辑器、SyncTeX 解析和 Tectonic 相关依赖。
- 仓库与产物扫描不得出现 WisModel 服务 Key、OAuth refresh fixed code 或用户 token。

## 14. 分阶段交付

1. 项目内核：目录模型、安全导入、主文件识别、快照事务。
2. 编译内核：Tectonic sidecar、bundle 安装、受控编译、诊断和 SyncTeX。
3. LaTeX 应用：编辑器、文件树、PDF 预览和项目状态。
4. Shell 集成：入口、标签、最近项目、恢复和打包。
5. AI Native：只读项目工具、多文件 Diff、确认写入、自动编译和撤销。
6. 跨平台打包、安全回归、E2E 和发布文档。

每一阶段均以独立测试和可回滚提交交付；在项目与编译边界未验证前，不接入 AI 写工具。

## 15. 风险与后续

- Tectonic 对传统 TeX Live 工具链、特殊宏包和系统字体的兼容性并非完全等价；MVP 明确展示“不受支持的包/工具”而不回退到任意外部命令。
- 完整资源包会占用用户磁盘和首次下载时间；UI 必须展示进度、目标目录和清理入口。
- SyncTeX 输出与 PDF viewer 坐标转换需要真实项目样本验证，失败时退化为错误行跳转，不阻塞编辑和编译。
- 目录项目放大了文件 watcher、外部冲突和快照配额问题，需要用大项目与异常 ZIP 建立基准。
- 后续多人协作应基于项目操作日志和授权模型设计，不直接复用本地文件 watcher 作为同步协议。
