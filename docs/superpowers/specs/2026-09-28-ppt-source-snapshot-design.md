# PPT 来源原文快照绑定设计

## 目标与边界

已批准的 PPT Agent 方案要求保留原始来源、可定位原文和页级证据。计划来源继续以 `uri` 表示原网址或已有 `attachment:<sha256>`；新增可选 `snapshotAttachmentId`，把原网址绑定到当前文档内已上传、已解析的原文附件。此字段不发起网络请求，也不证明网页真实性、附件与网址同源、主张正确或内容仍有效。

## 协议与兼容

- 旧计划的 `attachment:<sha256>` 继续可读；解析入口统一用 `presentationSourceAttachmentId` 得到实际附件 ID。
- 新计划可用 `uri=https://...` 加 `snapshotAttachmentId=<sha256>`。若附件 URI 与显式快照 ID 冲突，计划无效。
- 同一文档中的附件读取、摘录匹配、来源审计、主张证据窗口、复核记录和交付报告均使用该绑定。证据报告来源可含可选快照 ID，解析时以解析后的附件 ID 对照证据窗口；附件读取回执的 `sourceUri` 始终是 `attachment:<id>`。旧证据报告无新字段时，原摘要计算内容不变。无快照的外部来源继续产生 `source_original_not_frozen` 问题。
- 新字段进入计划摘要与冻结任务。旧版 PC 可能以 `invalid_plan` 拒绝新字段；插件不自动删除字段或把该错误误判为确切版本问题，工具说明提示检查 PC 版本。旧计划与历史报告按原语义解析。

## 失败与恢复

缺失、损坏、非文本或摘录不匹配的快照在编译前阻塞引用页面；补齐同一附件后可重试原任务。若改动快照 ID 或摘录，需保存新计划修订并启动新任务。文档隔离按现有附件服务执行；不跨文档查找同哈希文件。

## 验证与回滚

从旧计划兼容、快照绑定解析、整稿/逐页预检、证据窗口、来源审计、交付报告、插件状态协议和真实文本上传集成测试验证。异常值在任何持久写入前拒绝；历史计划无迁移。回滚代码仍可读取未使用新字段的旧记录；已保存的新计划需要新版 PC/插件继续执行，不自动降级。
