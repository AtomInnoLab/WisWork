# Agent 工具检查点顺序修正

## 目标

按 PPT Agent 方案 O1 的可恢复运行要求，使持久 `tool_completed` 只在工具产生最终结果后出现，并且在该结果交还 Agent 循环、进入下一工具或下一轮模型请求前完成保存。面板中断后仍以已保存记录为准，不把工具“已发起”误记为“已完成”。

## 现状与设计

`createOfficeAgentSession` 已在执行前等待 `tool_pending` 持久化，但普通工具的 `tool_completed` 是脱离主流程的异步写入；确认式工具更在等待用户确认之前就写入完成阶段。保留现有检查点格式和 `runId`，仅调整顺序：

1. 在第一次等待前捕获本次执行的 `runId` 和会话代次，等待 `tool_pending` 保存后检查该运行仍有效，才调用宿主工具；旧运行不得把完成标记写进新运行。
2. 普通工具返回最终结果后，等待 `tool_completed` 保存，再把结果交给 Agent 循环。
3. 原本返回 suspension 的工具及等待用户确认的提案，在最终结果真正结算后再保存 `tool_completed`，并在保存完成前保持 Agent 循环暂停。

后续补强：任一工具检查点写入失败时，Agent 核心接受受限的 `fatalError` 错误码并终止本轮，不执行同批后续工具或下一次模型请求。Office 保留原运行检查点供重开后核对，错误提示要求先检查文档，不提供一键重试。原 `tool_pending` 可能保留，恢复按钮仍不允许跨工具边界自动重放。本批不宣称完成任意工具执行中的全流程恢复，也不更改用户确认或宿主写入事务。

## 验证与回滚

测试用可控 Promise 验证普通工具和确认式工具在完成标记持久化之前不发起下一轮模型请求，且确认前不写完成标记；运行 Office Agent 定向和全量测试、类型检查。回滚仅恢复 `use-office-agent.ts` 原顺序，无数据迁移。
