# 现稿批量 ChangeSet 重新应用设计

依据：产品方案 v1.3 §15 阶段 5 的“保存点、差异摘要、撤销与重新应用”。本设计只扩展现有批量 ChangeSet；其它历史类型的重做仍按同一方案继续交付。

## 目标与边界

- `undone` 且原页包备份未释放的批量记录可从 Taskpane 保存点工作台发起 `reapply_existing_presentation_batch`，经实时读取、提案确认后逐步重做原操作。
- 对象被手工修改为第三值、非目标字段变化、原页备份不可读、备份已释放、文档身份改变时，在写入前拒绝。
- 每步继续使用既有宿主写入、目标回读和持久游标；Stop、写入成功但回执丢失、重开后的 `resume` / `undo` 沿用现有恢复路径。
- 重做后清除历史页面视觉复核，重新采集；保存点保持可供再次撤销。不得将历史 QA 标为当前通过。

## 状态与组件

`undone(cursor=0, backupReleasedAt=undefined)` 经确认和备份读取进入 `applying(cursor=0)`，然后逐步进入 `applied(cursor=N)`。确认前不修改宿主或记录。转换时清除 `reviews`；每步的游标与状态仍通过既有 `writeExistingBatch` 校验。`undone` 且备份已释放不可进入 `applying`。若首步写入回执丢失，现有 `applying(cursor=0)` 核对逻辑识别宿主已写入，允许继续或撤销。

修改范围：批量工具定义与执行、持久状态转换、Taskpane 保存点工作台动作、宿主 QA 失效范围、对应回归与阶段台账。不得扩张为跨类型通用重做或伪原子事务。

## 验证与回滚

先用失败回归覆盖撤销→确认重做→重开再撤销、备份释放/缺失/手改冲突拒绝、首步回执丢失恢复和受影响页 QA 失效；再实现。运行 Office 插件全套测试、类型检查、lint、格式与 diff 检查。真实 PowerPoint 保存重开仍需单独验收。回滚代码提交即可恢复旧工具目录；既有 `undone` 记录保持可读，新增 `applying` 记录仍可用旧版 `resume`/`undo` 恢复。
