# Office Safe Diagnostics and Markdown Design

## Goal

Make Office editing failures diagnosable without exposing document or account data, and render Agent responses as a safe, streaming-tolerant Markdown subset in the taskpane.

## Non-goals

- Do not upload document text, prompts, Agent output, tool input JSON, formulas, OOXML, screenshots, attachments, tokens, capabilities, verification codes, email addresses, raw Office error messages, or stack traces.
- Do not accept arbitrary HTML, script, remote images, or unsafe links in Markdown.
- Do not turn the Relay into a general telemetry or log-ingestion service.

## Architecture

The taskpane maintains a bounded in-memory diagnostic ring for local export. After an Office/PC session is approved, it may send strictly validated failure diagnostics over the existing capability-bound Relay WebSocket; the Rust Relay writes only the validated structured event to its operational log. Diagnostic failure must never interrupt pairing, Agent streaming, approval, or Office writes.

Assistant messages use the existing dependency-free `@wiswork/ui` Markdown renderer. The renderer remains a deliberately small subset and treats unsupported or partial streaming syntax as text; no raw HTML or URL/image authority is introduced.

## Diagnostic Event Contract

Protocol v2 adds `office.diagnostic` with exact keys:

- `version: 2`
- `type: "office.diagnostic"`
- `session_id`, `capability`
- `event_id`: random UUID generated by the taskpane
- `trace_id`: random UUID for one Agent run
- `timestamp_ms`: client wall-clock timestamp
- `host`: `word | excel | powerpoint`
- `platform`: bounded allowlisted Office platform label or `unknown`
- `build`: bounded deployed taskpane build identifier
- `tool`: bounded tool name or `unknown`
- `phase`: `tool | proposal | validate | write | verify | recovery | transport`
- `outcome`: `failed | unsupported | cancelled`
- `error_code`: allowlisted stable WisWork error code
- `office_error_code`, `office_error_name`, `office_error_location`: optional, bounded, printable identifiers only
- `duration_ms`: bounded non-negative integer
- `requirement_sets`: bounded map of known requirement-set names to boolean support

The Relay authenticates the event against the live Office session and Office capability, enforces exact schema and byte/rate limits, and never forwards diagnostics to the PC. It logs a structured event with connection/session correlation but never logs the session capability.

Limits:

- At most 4 KiB serialized per event.
- At most 100 accepted diagnostic events per session.
- Taskpane local ring contains at most 200 events.
- Production automatically uploads failures only. Successful lifecycle events remain local.
- Remote upload is best effort and cannot change application state on failure.

## Local Diagnostic Export

The taskpane exposes “Copy diagnostics” from its management panel. Export is bounded JSON containing build/host/platform/requirement support and recent sanitized events. Clipboard failure is shown locally with a stable safe message. New task may retain diagnostic history for troubleshooting; logout, session revocation, and taskpane disposal clear it.

## Error Capture

Adapters retain the privacy-preserving public error codes. A diagnostic helper may inspect an Office exception only long enough to extract allowlisted identifier fields (`code`, `name`, `debugInfo.errorLocation`); it never retains or serializes `message`, `stack`, `debugInfo.statement`, or arbitrary nested values. All unknown values become `unknown` or are omitted.

## Markdown Boundary

Render only assistant timeline messages as Markdown. User messages, errors, tool activity, approval content, and diagnostic output remain plain text.

Supported subset:

- paragraphs and line breaks
- headings rendered with chat-safe visual hierarchy
- ordered and unordered lists
- bold, italic, and inline code

Unsupported Markdown, raw HTML, links, images, fenced HTML, and incomplete streaming tokens render as text. React text escaping is the final HTML-safety boundary.

## Failure Handling and Rollback

- Unknown or malformed diagnostic frames fail closed without terminating an otherwise valid Agent request.
- Diagnostic queue/rate/serialization failure is dropped locally and recorded as one bounded local `diagnostic_upload_failed` event without recursive upload.
- Disable remote diagnostics with `VITE_WISWORK_OFFICE_REMOTE_DIAGNOSTICS=0`; local export remains available.
- Roll back the protocol by deploying a Relay that ignores no new frame only after rolling back the taskpane flag/build. Markdown can be independently rolled back to plain text rendering.

## Verification

- Rust protocol tests: authentication, exact schema, redaction, size/rate bounds, wrong session/capability, and no PC forwarding.
- Taskpane tests: phase/error capture, prohibited-field absence, ring/clear limits, best-effort upload, trace correlation, and clipboard export.
- Markdown tests: supported subset, raw HTML escaping, unsupported links/images as text, streaming partial syntax, and user/error messages remaining plain text.
- Full Office, Relay, typecheck, lint, format, theme, license, build, and diff checks.
- Manual Mac/Windows Word and Excel reproduction must show a trace in local export and the matching sanitized Relay event.
