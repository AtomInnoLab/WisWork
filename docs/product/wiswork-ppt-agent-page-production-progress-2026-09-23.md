# PPT Agent：持久化页级编译与失败页续跑

日期：2026-09-23。基线：`f73f02f7`；分支：`codex/ppt-agent-implementation`。

## 1. 目标与方案依据

依据原方案 §4.5 SlideTask、§5 阶段 E、§11.6 双编译路径、O1/O3、§20/21，实现 PC 页级生产任务及插件恢复入口。原方案继续作为开发和验收权威；O1/O3、总体阶段1/3与P0仍为**进行中**。

## 2. 本批完成项

- 冻结已保存计划版本和完整 SlideIR，逐页调用现有 PptxGenJS 编译器；每页只解析所引用素材和主张。
- 持久化待处理、编译中、已编译、失败四种状态、尝试次数、错误与单页 PPTX。单页失败后继续其余页面；相同任务续跑跳过成功页。
- 支持服务重建后续跑、取消后保留已完成页，以及重试中断遗留的编译中页面。任务和产物绑定文档，输入冲突拒绝，写入使用原子保存、摘要校验和页级并发检查。
- 插件新增创建、执行、读取页任务及读取单页产物工具。项目卡显示逐页状态与继续入口；旧任务使用旧计划时明确提示。
- 单页 PPTX 可独立下载；Agent 开始/运行后刷新项目卡。会话清理和取消防止迟到结果发布。

## 3. 验证证据

- 全仓 `npm test` 通过：5,994项 Vitest 测试，其中 Office 插件793项、Shell 326项；既有脚本与原生测试通过。
- 全仓 `npm run typecheck` 通过；首次发现附件回调参数类型不匹配，修正后完整重跑通过。
- 全部变更 TypeScript/TSX ESLint、`git diff --check` 通过。
- 测试结束后 Office 插件和 Shell 生产构建通过；插件保留大于500 kB的分包提示。
- 独立审查无剩余重要发现。审查发现项目卡刷新等待期间清理会话/取消会迟到返回成功，已修复；两个回归先失败后通过，Shell本批跨层测试共8项通过。

工程集成使用已有合成8页样本和真实 PptxGenJS：注入第3页失败，其他7页完成，重建服务后只补失败页；逐页重新解析，检查原生表格和图表；覆盖取消、缺失图片、重复执行、旧计划冻结、跨文档拒绝、插件下载与项目卡继续任务。该样本不替代20项真实专业任务。

## 4. 未完成与边界

- 本批完成 PC 页级编译，尚未将这些页产物接入逐页 Office 写入、回读和验收。没有新增宿主写入，也不宣称完整连续生产或整稿交付。
- 当前一次执行顺序处理剩余页并保存状态，未实现运行中逐页推送或完整业务语义事件重放。
- 相同任务输入冻结；内容或样式调整需要新任务，尚无跨任务复用成功页或只更新受影响页的依赖模型。
- 不合并单页 OOXML：现有合并函数不能保证备注及图表关系保真。后续交付需沿用可靠编译/导入路径。
- 内容/证据 QA、真实 RoundTrip、首批单页重做与撤销仍待完成。20项真实材料包待准备，真实 Office 执行未开始，P0完成率未测量。

## 5. 风险与限制

降低单页失败导致整稿重复编译的成本。新增页产物存储与版本状态；累计单任务 PPTX 原始字节限制10 MiB，每项目最多32个页任务，单页报告48 KiB，继续遵守既有请求/响应限制。页任务由同项目服务锁串行处理；无跨进程写入协调。达到限额会失败，未实现任务清理产品入口。

已编译不等于已导入或验收通过；编译报告继续保留渲染未执行、来源未核验和 RoundTrip 未执行。
