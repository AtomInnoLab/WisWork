# PPT Agent：认证团队项目、明确发布快照和审阅评论

日期：2026-09-29。依据原方案 v1.3 阶段 6 / P2，实施分支 `codex/ppt-agent-implementation`。本批实现认证团队链路基础，实际网页账号登录与团队用户界面仍待接通；不宣称生产团队功能完成。

## 完成内容

- **PC 团队账本**：所有者、审阅成员和只读成员；九项服务操作包含认证身份、仅所有者计划预览、创建/读取团队项目、成员授权/撤销、明确发布新计划、添加/解决评论。ACL 和完整已发布计划同文件原子保存，严格 CAS、32 成员/128 评论/768 KiB UTF-8 配额、损坏和符号链接拒绝。
- **来源共享**：成员只读用户确认发布的精确快照，私人计划修改不会自动发布；来源摘录随快照共享，原始附件字节不通过该协议传输。新计划发布保留评论原计划版本，历史评论不重绑当前页面或来源。
- **认证传递**：PowerPoint 专用 `presentation-team.v1` 独立会话，禁止共同协商旧私有能力。Relay 复用现有 OIDC 校验，传递真实成员和配对 PC 的主体摘要并剥离令牌。PC 上下文不来自 Agent 请求体；普通能力不能执行 `team_*`。
- **Office 提案工具**：八个团队工具接入 Runtime 和 ACP；写入都需可见确认，确认前不写文件。完整来源 ID、计划摘要和共享范围在有界预览中展示，明确裁剪/遗漏、完整字节数和 SHA；实际发布保持完整计划。成员评论作者取自可信上下文，不接受作者参数。只读来源预览走认证所有者接口，完全不调用旧 `get_plan`。
- **写入身份绑定**：所有团队写请求携带由预览闭包捕获的 `expectedIdentity`；PC 与已认证上下文比较，失配先拒绝，不用它授予权限。即使切换到另一个已有审阅权限的账号，也不会误保存评论。
- **兼容与恢复**：旧项目服务两参数调用和原能力保留；团队要求明确能力协商。团队文件重开保留 ACL、来源和评论；同 ID/同作者/同内容评论支持 ACK 重试，撤权立即阻止读取和重试。团队变更不改 PowerPoint 页面、不失效页面 QA，不代表事实或视觉验收。

## 独立审查发现与修复

1. 完整计划超过提案指纹 512 字符限制：改摘要指纹，完整快照仍参与确认前比对。
2. 合法约 90 KiB 来源计划超过 64 KiB 预览预算：改明确有界摘要，不放宽预算、不截断真实发布内容。
3. 两个已授权审阅账号在写入时切换：新增否定型身份前置条件，PC 写入前拒绝；真实文件验证评论为空、修订未变。
4. OIDC 验证期间同连接取消/断线被串行处理延迟：团队请求认证期间继续读取取消与断线，丢弃认证 future；慢本地认证夹具证明 PC 零转发。
5. 团队连接与旧私有能力混协商可能绕过快照权限：三端拒绝混协商；源预览使用仅所有者认证接口。旧用户明确批准的独立私有连接仍按原权限运行，不把它说成团队只读连接。
6. 确认时传输错误可能直接显示令牌样例：只返回明确安全错误码。

连接、身份和 Office 对象均为工程测试夹具；使用真实 PC 文件和实际提案控制器验证持久行为，本地 OIDC HTTP 服务验证令牌处理。它们不等于生产身份提供方或真实 PowerPoint 验收。
