# PPT Agent：团队共享与审阅工作台

日期：2026-09-29。按原方案 v1.3 阶段6/P2推进，接续认证团队基础源码 eae59ec3、台账473a4fb9。上轮已接通 PC 认证权限和共享协议；本轮实现团队工作台控制器、角色界面及现有确认卡接线。实际 Office 网页登录与独立团队连接尚未配置，不宣称当前生产用户已经能登录团队。

## 完成内容

- 团队卡片接入实际 PowerPoint 工作台及 `createOfficeWorkspaceUi`，其他宿主不显示该入口；未连接时显示真实不可用状态。
- 用户可明确读取团队、查看认证账号与角色、已发布计划和完整来源列表。所有者可创建/发布项目、授权或撤销成员；审阅成员可添加评论和解决自己的评论，只读成员不显示写入入口。评论目标来自已发布页面、主张或来源；历史评论标明原计划修订，不当当前内容通过审阅。
- 发布、授权、评论和解决都通过已审核团队技能生成提案，复用原全局确认卡。卡片和控制器不另设自动确认通道，不直接调用 PC 写接口。团队确认反馈明确显示团队记录保存，不把它说成修改了宿主文档。
- 控制器捕获实际账本修订、账号和文档，确认后读取真实持久结果；CAS 冲突和撤权清空未经重验内容，未知错误只显示安全码。取消不写共享状态，不重新展示旧 ACL；用户明确刷新再核对当前权限。
- 缓存快照引用稳定且冻结，清理/文档变化/账号变化/迟到响应有隔离守卫。控制器生成提案后即跟踪其 ID，清理时只取消自己拥有的提案，旧请求不能取消新的提案。
- 已成功读取的团队 ID 自动同步到输入框。内容清空后只保留已知的请求目标 ID，刷新仍须重新认证和检查 ACL；成员、来源和评论不会随 ID 留在界面中。
- Runtime 会话清理与销毁同时清理团队控制器。真实提案成功前无 PC 写入，团队写入不影响宿主 QA 状态，也不需要模型调用。

## 验证范围

实际 React 操作验证界面动作与角色限制；实际 Runtime、Office session、团队技能、原确认控制器和 PC 文件共同验证创建→确认→成员授权→评论取消/重新提案→保存→撤权→内容清空。包括模型 transport 零调用、宿主 QA 零失效。测试中的认证身份为合成可信主体；没有使用真实 OAuth 账号或 PowerPoint 进行验收。

独立审查发现并修复：提案生成后、UI 状态登记前清理可能漏取消；取消/失败直接恢复旧快照可能重显已切换账号的内容；旧请求捕获的提案 ID 不能影响新提案；读取末尾连接失效必须拒绝发布结果，卡片也不显示不可用状态里的残留内容。根集成还确认了通用“Document updated”反馈不适用于团队元数据，已改为团队保存反馈。确认后读取是异步操作，测试等待实际刷新完成；取消后的共享内容由明确刷新重读，不依赖旧快照。
