# PPT Agent：统一变更历史与逐项撤销

日期2026-09-24；基线ebcd9aa3；隔离分支codex/ppt-agent-implementation。按原方案§6.2/6.4、O5继续实现，原方案不变；实机验收0/20继续暂缓。

## 本批完成

1. **四类统一历史**：文字、位置尺寸、图片、整页替换保留独立记录，新修改不再覆盖文字/几何旧保存点。新记录有稳定序号，状态变化保留原序号；首次导入旧保存点明确标记顺序未知。
2. **与原保存点同次保存**：历史和原设置key同一次Office settings.save提交，保存失败回滚两者；无法证明回滚或发现旧版本只改了其中一侧时封锁相关读取/写入，避免用不一致的历史恢复宿主。
3. **按记录读取、检查、撤销、恢复**：8个文字/几何工具支持可选change_id，显式ID不存在时不会退回最新记录，确认前后固定同一记录并保留原有文档/任务/页/对象/当前值检查。旧调用不传ID时继续使用当前最近slot。
4. **统一工作台与Agent入口**：工作台优先显示当前成果的历史，按记录执行动作；list_presentation_changes输出限量摘要，包含作用范围、操作描述、保留要求、验收要求和保守风险级别，不输出全文或图片字节。
5. **容量与未决保护**：最多64条、历史及后续状态增长预留共1MiB；现有各类记录预算继续生效。达到上限在宿主写入前拒绝，不自动驱逐保存点。未决记录阻止新事务，既有未决仍可沿原方向恢复。

## 已验证的主要流程

真实Office设置绑定、运行时、提案控制器、工作台配合模拟宿主：文字修改1→位置尺寸修改→文字修改2→重开→列出3条记录→按记录撤销文字2→位置尺寸→文字1。原记录全部保留，最后一项回执保存失败时恢复只补记录、不重复宿主写入；无关页面QA不失效。先撤销与现状冲突的较早文字记录会被拒绝。

存储回归覆盖同类多条、跨类型顺序、较早ID/CAS、重开、旧数据迁入、两key保存/回滚、Save As、损坏或旧版分歧、公开图片读取一致性，以及容量达到上限和未决保护。摘要工具覆盖不同文档/请求/来源/页/产物隔离、非法输入、重复记录、clear和任务切换丢弃旧响应。部分既有测试原先直接覆盖slot、或连续制造新的pending，现按历史一致性和未决规则分别改为真正旧数据夹具。

## 能力边界

这是**单操作ChangeSet摘要与逐条历史撤销**。intent是操作类型描述，不冒称存下了用户原话；validation列出待满足要求，不表示QA已通过；risk沿用保守确认级别，没有新增自动低风险放行。未实现多操作原子变更集、redo、任意现稿DeckBaseline或完整选区/批量规划。

逐条撤销复用各类型原有条件，不是可以越过对象依赖的全局Undo栈。图片或整页恢复会产生新宿主ID，较早记录仍绑定旧对象时拒绝，不自动重映射或强行覆盖。整页替换仍保留原有“当前未完成替换不能被下一次替换覆盖”的约束，较早整页终态仅供查看。

历史序号是原修改的加入顺序，不是每次撤销/恢复事件的完整审计时间线。旧slot仅提供曾保留的最近记录，不能补回此前已覆盖的数据。最多64条与1MiB按先达到者停止，长文本/整页预留可能更早达到上限；没有自动清理或用户历史归档入口。每次写入仍须提案确认，截图QA与实机验收独立。

无新依赖，无后台迁移，无删除用户历史。旧版本不维护新历史，降级再升级若发现不一致会拒绝历史操作；不宣称降级后仍有完整新历史支持。
