# PPT Agent：单页替换暂存与撤回

日期：2026-09-23。基线`e0e65046`，分支`codex/ppt-agent-implementation`。

## 1. 对应原方案

本批按原方案§6.4、O3、O5、§21继续实现写前保存点、写入回执和可恢复事务。已有单页重编译及PC原页备份，本批允许将修订页**暂存到原页之后**，并可确认撤回该暂存页。原页与原业务映射保留。正式替换、整页撤销及P0仍为进行中，不调整原方案验收范围。

## 2. 完成内容

- 插件新增stage/inspect/resume/discard四个单页替换暂存工具；写入和撤回都有具体页面、备份与影响说明，由用户确认。
- 文档设置新增独立事务记录，保存文档、父子任务、业务页、备份、原宿主页、原页序、包内容指纹及新宿主页ID；CAS串行保存与不可变身份校验，不允许未决记录被另一个项目覆盖。
- 写入前保存`pending`，只在原内容和页序仍匹配时将修订单页插在原页之后；回读唯一新增ID后先保存`inserted`，包内容验证后保存`staged`。本批没有删除原页。
- 已知新页ID的`inserted`记录可以重新检查并确认补全回执，绝不重复插入。尚无新页ID的`pending`不自动重试，需人工核对。
- 撤回先保存`discard_pending`，只删除身份、内容和位置仍匹配的暂存页；回读恢复原序后保存`discarded`。若删除已完成而状态保存中断，重新确认只补回执。
- 内容指纹按ZIP中排序后的路径与条目SHA-256计算，忽略ZIP容器时间戳和压缩方式，保留OOXML内容、关系与资源差异。新指纹路径按实际解压字节限制内存，不先对整包做无界CRC解压。
- 复用PC备份加载与生产页产物校验，不创建额外会话文件；生命周期清理、切文档、活动父成果/回执漂移均阻断旧确认。暂存操作使原页关联QA失效，不伪造新页验收。

状态流转：`pending → inserted → staged → discard_pending → discarded`。新的暂存任务只可在上一事务已撤回后开始。

## 4. 边界与剩余风险

- 这是替换的暂存阶段，会临时出现原页及修订页两页；没有切换业务页映射、删除原页或完成整页撤销。派生任务仍禁止整批导入。
- 指纹保守比较所有条目内容。真实Office导入后可能改写关系、ID或元数据，这时会停留`inserted`并报告冲突，保留原页；不得放宽验证假装通过。真实Office可重开及20项材料验收仍待执行。
- 未决`pending`不具备已知新增页所有权，不会因重试插入另一页；当前只提供检查，人工核对的最终解除流程尚未开放。
- Office.js没有跨导出、文档设置与删除的原子CAS。实现尽量在写前完成最后一次内容/身份/页序校验，但不能保证阻止最后一次读取与写入之间所有共同编辑竞态；需要真实宿主并发验收。
- 暂存内容、原页或页序被用户改动时停止自动处理。保留备份及记录，不自动删除看起来相似的页面。
- 事务记录最多192KiB，最多512个原宿主页；暂存新页额外占一页。浏览器指纹沿用更保守的包限额：原包/总解压8MiB、单条目2MiB、256项，可能拒绝PC已存但超出该子集的备份。
- PC备份仍受此前8份/项目等限制。旧版本插件不理解新事务，不应在未决事务上继续旧流程；回滚保留原页、暂存页、事务记录与PC备份。

## 5. 部署与回滚

本批不合并、推送或部署。Taskpane新增工具/adapter及settings key；PC/Relay/Manifest接口没有新增变更。App通过现有document binding接线自动获得新日志方法。旧文档不迁移，既有导入回执和几何/图片记录不改写。
