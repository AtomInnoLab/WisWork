# 演示项目审计到期与最小墓碑阶段记录

日期：2026-10-01。依据原方案 §13.1 的内容保留、审计期限和删除后防复活要求。本阶段只在本机合成目录验证，未对真实项目执行删除。

## 本阶段目标与完成项

项目内容删除完成且 `auditRetentionDays` 到期后，PC 保留期扫描会将原路径 `lifecycle.json` 原子替换为 v2 最小墓碑，不再持有其中的事件、资源 ID、项目 ID 和文档 ID。墓碑仅含已删除状态、项目与文档身份 SHA-256 摘要及清理时间。新版 PC 把它识别为已删除；旧版 PC 的 v1 严格解析会拒绝该文件，不会将项目误判为缺失而重新创建。未删除项目、审计期限未到或期限为 `null` 的项目保持原控制记录。

替换使用已有同步写入与重命名门禁；中断时磁盘上保留旧审计或完整新墓碑，不产生“控制文件缺失”的中间状态。每次扫描新增 `pruned` 计数，便于区分审计清理与内容删除。原 v1 控制记录读取、删除执行及策略接口不改格式。

## 验收证据与边界

本机测试覆盖到期边界、最小墓碑不含原始身份与资源 ID、跨文档拒绝、旧版解析拒绝 v2、注入重命名失败、保留期扫描和重开后读/写/创建租约拒绝。生命周期、删除、写租约、治理七组串行及最终并行回归均 **99/99**。首次并行运行有一项保留期受理测试失败；该用例单独、所属文件、串行全组与最终并行全组均通过，尚未定位首次失败原因。Project Store 与 Shell 类型检查通过。

墓碑中的确定性摘要仍是与已知项目/文档身份可关联的伪匿名标记，不应作为完全匿名数据。保留期自动执行仍须 PC 两个显式开关，默认关闭。真实项目清理、真实 PowerPoint 工作流、专业材料验收和跨平台验证未执行；本阶段不提升严格整体成熟度，仍为 **64%（575/9）**，真实专业任务 **0/20**。
