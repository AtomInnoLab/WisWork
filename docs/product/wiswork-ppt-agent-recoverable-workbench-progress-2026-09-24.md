## 本轮目标

用户要求一次推进多个关联任务。本轮依据原方案 O1，将冻结页面的后台生产、任务控制、持久事件、工作台恢复与成果操作一起接通，包含多个请求共存时的活跃任务定位与旧任务选择。原方案保持不变，实机验收按用户要求继续暂缓。

## 完成范围

| 关联任务       | 实现                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 后台页生产     | PC 接纳后独立执行，客户端 Abort/关闭面板不取消后台任务；同项目防重复启动，跨项目独立                                                 |
| 暂停/继续/取消 | 在当前页保存完成后暂停或取消；成功成果保留；继续只编译未成功页；取消任务不自动重新启动                                               |
| 中断恢复       | Job 绑定文档、请求、冻结输入及计划摘要；PC无活跃worker时识别中断，显式继续；重新打开面板读取PC持久状态                               |
| 生产时间线     | 任务开始、页开始/成功/失败、暂停/取消/中断/完成；原子存储、摘要校验、revision CAS；最近128事件连续回放，更早历史截断明确提示         |
| 项目工作台     | 当前状态、完成页/失败页、下一动作、后台控制、活动任务轮询；文档变化及取消后的过期响应不发布                                          |
| 成果交接       | 已完成单页保存到会话附件，可下载；全部编译完成后准备既有导入流程，仍需既有确认与QA                                                   |
| 兼容           | 新PC操作独立，旧前台编译接口保持；旧PC明确提示升级并保留前台继续路径；无新增外部依赖和旧数据迁移（插件补声明现有本地共享契约包依赖） |

## 关键边界

- 后台任务执行的是已有冻结 SlideIR 的逐页编译；不声明研究、LLM规划、宿主写入已具备后台自动恢复。
- 本轮时间线是生产阶段恢复视图，不是完整研究到交付的全量审计日志。
- 暂停/取消请求刚接纳时显示“当前页完成后生效”，不提前显示已停止。
- PC进程重启后不会未经指令自动继续；已编译页仍可读，剩余页可显式继续。
- 生产页回执与Job事件为独立原子文件；若两次写入之间退出，以已保存页面成果为准，任务标为中断，不能猜测丢失事件。
- 同一Electron进程共享任务注册表，不提供跨PC进程分布式并发保证。
- 编译完成/准备导入不等于Office写入、内容来源核验、视觉验收或保存重开通过。

## 完整工程场景

真实8页基准经真实PptxGenJS编译：开始→当前页暂停→创建较新任务但仍保持运行中旧任务可见→关闭旧Taskpane运行时→新运行时选择旧暂停任务恢复→保存已完成单页→继续（注入一页编译失败）→只重编失败页→8页成功→准备既有导入。断言7个成功页各只编译一次，失败页两次；文件/Job真实持久化，无宿主或QA写入。
