# PPT Agent 第三批实施报告：可恢复的制作计划

## 状态

**本批工程交付已完成，整体方案仍在进行中。**

基线 `34a04f3`，继续在 `codex/ppt-agent-implementation` 独立分支实施。本批对应 O1 项目模型基础，连接“规划 → 保存 → 恢复 → 编译”。未合并、未部署。

## 已完成

- **版本化制作计划**：保存目标、受众、语言、时长、必需内容与约束；来源摘录及定位；主张类型、来源引用、置信度与计算说明；共享字体/色板；有序逐页施工单、素材需求和验收条件。
- **计划独立于编译持久化**：尚未生成 PPTX 时也能保存、重开并查看项目。以当前版本号保存，拒绝陈旧版本覆盖；相同请求重试不重复增加版本。
- **保存／读取 Agent 工具**：`save_presentation_plan`、`read_presentation_plan`；恢复后返回计划版本和编译所需的确定性主张映射，并生成会话中的计划 JSON。
- **编译关联计划**：已保存计划的项目，新增编译请求必须指定当前 `plan_revision`。校验项目、标题、样式、页面顺序/ID/标题/主张引用及主张映射；错误版本或结构不符会拒绝。
- **不可变编译证据**：每次请求保存当时的计划快照。更新计划后，旧请求重试仍返回原成果；不会用新计划悄悄替换旧请求依据。
- **Taskpane 计划视图**：展示制作目标、来源、主张、样式和逐页目的。当前计划与旧编译成果分开标识，提示“已有成果不代表当前计划”。
- **输入与恢复保护**：限制引用、字段、大小与展开后的编译体积；拒绝虚假已核验状态；取消/新任务/文档切换后不发布迟到结果；读取或保存另一个项目失败时不丢失原项目选择。

## 验证

- Schema、存储、服务、工具与 UI 均增加了行为回归测试，先观察失败再实现。
- 真实端到端测试：保存计划 → 重建服务/插件 → 恢复来源与计划 → PptxGenJS 生成并重新解析 8 页 PPTX → 修改计划 → 重试旧请求保持原字节 → 过期版本的新请求被拒绝。
- 独立审查发现并修复来源展开导致的字符预算、UTF-8 传输预算问题；重复长来源不再产生必然无法编译的有效计划。
- 最终全仓 `npm test` 通过（Vitest 共 5725 项通过，含 Office 插件 578 项、PPTX 引擎 575 项）；全仓 `npm run typecheck`、变更 TypeScript/TSX 文件 ESLint、Taskpane 与 PC 生产构建、`git diff --check` 均通过。

构建测试曾因默认 10 秒初始化等待超时失败。单独运行的 4 项构建断言全部通过；仅将该 Vite 构建初始化的等待上限设为 30 秒后，插件整套与全仓测试均通过。没有修改产物断言或全局超时。共享存储还修复了 Sheets 严格可选属性类型检查下的兼容问题。

## 仍然没有完成的能力

1. 这是 **O1 的结构化计划与恢复基础**，不是完整的项目执行状态机、ACP 阶段时间线或页级调度。
2. 来源只做登记和可追溯映射，所有主张仍为 `needs_review`；未自动核验事实、时效、法域或计算公式，也没有把公式作为代码执行。
3. 编译契约检查元数据和引用一致性，不证明正文语义、必需内容、素材需求或验收条件已经满足。
4. 样式目前绑定已有字体与色板；完整网格、组件库、品牌包尚未实现。
5. 计划最多 32 页，JSON 上限 192 KiB，必须展开的编译数据也受 192 KiB UTF-8 预算约束；实际编译请求仍受 256 KiB 总上限约束。大附件与大图片需后续 O2 管线。
6. 不包含真实 PowerPoint 渲染/保存重开验收或 20 个专业任务基准；完整 P0 仍未验收。
