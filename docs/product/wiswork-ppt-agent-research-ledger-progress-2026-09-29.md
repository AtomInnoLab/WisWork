# O1/O2/O4：独立研究账本与可恢复原文绑定

日期：2026-09-29。依据原方案 §4.3、阶段 B、§7.1 和 `build_research_ledger` 工具。研究先于计划，原方案及退出门槛不变。

## 完成范围

1. 新增独立 ResearchLedger，不要求已保存制作计划或已有生产任务。Agent 通过既有检索/资料工具读取原始材料，再提交作用域、来源、结论、建议页面、声明可信度/来源等级及冲突引用。事实、引文、计算、判断和假设明确区分，全部保持 `needs_review`；来源或证据不足不被包装为核验通过。
2. 严格共享 Draft/Record/History/Summary 契约和完整工具 JSON schema。检查 ID、日期、来源 URI、跨引用、重复、自引用、计算字段及 UTF-8 总量；最多 64 来源与 64 结论。冲突双方保留，按无向关系计数；建议页面不证明实际宿主页面存在，声明等级与可信度不是来源认证。
3. 复用真实文档附件服务核对原文摘录、位置和网页原始地址。用户提供材料与实际抓取网页分别标注；网页只有原文快照就绪、地址完整摘要匹配才记录 `fetched_url_matched`，检索时间来自原快照。缺失快照、摘录缺失、空引文、未就绪、不支持和来源不符保留结构化缺口；位置同时保留草稿引用与实际匹配位置，不能由字面匹配推断语义支持。
4. 整理开始先持久保存，实际核对后保存 completed 或安全 failed；开始/结束是整理操作时间，不代替来源检索时间。元数据原始文件摘要与附件 ID 绑定；既有原文 matcher 校验其持久 textDigest，但公共旧回执不暴露 parsedTextSha256，因此本批不伪造该可选字段。
5. 本机 PC 独立研究存储使用校验和、严格路径/符号链接拒绝、有界读取、原子项目状态及写入同步。项目 CAS，稳定研究 ID + 相同草稿幂等；不同草稿同 ID 拒绝。最近 32 条摘要窗口、完整 128 条归档、64MiB 上限；已完成、失败和未决记录可重开读取，不自动重放。到达容量上限拒绝新写、已有记录仍可读；本批没有删除研究历史入口，后续显式归档清理继续待做。
6. 独立能力探测、build/list/read/latest 操作沿用 `presentation.v1`。最新已完成结果从完整归档读取，不被最近 32 条失败/未决记录遮住。旧 PC 不支持时隐藏；历史操作保持严格文档/项目隔离，损坏存储不删原资料。
7. 实际 Office 工具接通 build/read/list/export，完整 JSON 和可读 Markdown 原子写会话附件；保留推断、来源原文、冲突双方、检索时间和未核验项。取消、清会话、文档切换、迟到响应和未知回执均有隔离；响应丢失后只读找回，窗口外旧 ID 重试仍返回原归档，不新增整理。
8. 独立 ResearchController/Card 接入真实 HostRuntime、App 和工作台，无计划/生产时也可见。展示来源/结论/冲突数量、作用域、历史状态、结论与推断、可点来源和缺口，默认折叠详情；支持选择项目、刷新、读记录及导出。能力探测已成功但列表暂时失败时保持入口及安全提示，不隐藏可恢复研究；未决记录不宣称后台仍运行。
9. 当前宿主交付 ZIP 可附成对 `research.json/.md`，PC 核对同文档/项目、completed 状态及原归档完整内容，各文件摘要纳入 manifest。研究附录明确是项目历史整理结果，与生产任务冻结证据分开，不证明当前宿主结论或事实通过。新 ZIP 最大 12 条目，文件总量/压缩/解压上限不扩大。原有导出与旧包读取保持兼容。
