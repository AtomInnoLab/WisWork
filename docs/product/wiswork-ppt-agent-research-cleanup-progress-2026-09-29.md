# PPT Agent：研究归档清理与引用保护

日期：2026-09-29，依据原方案持久项目、资料管线、容量治理与恢复要求。仅实现清理能力并使用合成临时目录验证，没有对真实用户资料执行清理。

## 完成内容

- 研究记录的 128 条配额按现存记录计算，用户明确确认后可清理已结束且未引用的归档。原附件、PowerPoint 文稿、交付 ZIP 与导出副本保留；Agent 没有注册删除工具。
- 首次清理才将历史迁移到 V2，保留原研究 ID、序号、草稿摘要；新记录持续递增序号。原 V1 历史保持兼容，旧客户端遇到 V2 明确要求升级，不伪造连续历史。
- 删除回执固定绑定文档、项目、记录、草稿摘要、删除身份和修订；相同请求幂等恢复。最多保留 4096 条墓碑，已删除 ID 永不复用；达到墓碑上限拒绝新清理。64 MiB 归档上限保持。
- PC 用同一个项目锁串行执行清理与计划绑定、恢复、编译、生产和交付上传。当前计划、可恢复历史计划、所有冻结编译和生产计划保护原研究；引用记录损坏时拒绝清理。含研究副本的未完成交付上传阻止清理，已完成 ZIP 保持独立可读。
- Office 面板提供二次确认、停止等待、只读回执查询和显式重试。只持久化有限恢复身份，不在浏览器保存研究原文；关闭面板后恢复身份并只读核对，不自动重发删除。旧 PC 能力隐藏清理入口。
- Agent 和面板严格协商能力与 V2 历史。实际跨层测试发现并修正“序号不能超过现存记录数”的旧假设，清理后的新研究可以正常创建。

## 验证

Store 定向 **17/17**，PC 定向 **25/25**，Office 面板/控制器 **20/20**。实际 PC→Agent 集成核对清理后 V2 历史、新建序号、重启回执和冻结原证据；能力协商覆盖旧精确响应、一次回退及异常响应拒绝。128 条真实测试记录清理后可新建序号 129，4096 条合成有效墓碑达到上限时不会丢失已有档案。

完整相关回归 **2860/2860（222 文件，108.82 秒）**。独立复核发现并处理两类边界：当前计划或项目元数据丢失但历史资料仍存在时，清理拒绝；明确未提交的业务拒绝释放待核对请求，清除浏览器恢复元数据失败时安全保留请求并显示错误。网络、取消及回执不确定情况仍保留固定身份。最终补充回归 **83/83（9 文件，10.39 秒）** 覆盖修正后的 Store 原接口、PC、Agent 和面板；没有把完整回归的旧统计改成最终新增测试总数。
