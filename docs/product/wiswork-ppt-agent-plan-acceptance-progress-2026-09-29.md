# O1：真实计划与样式接受决定

日期：2026-09-29。依据原方案 §7.1、§7.3 和 O1，原方案保持不变。

## 完成的跨端链路

- 当前计划工作台提供可选“接受当前计划与样式”。这是明确用户决定，不是普通制作的新确认门禁；保存计划、编译或工具成功仍不生成批准。
- 插件提交决定 ID、显示版本与完整计划摘要；决定 ID 固定绑定文档、项目、精确版本及摘要，用户显式重试也保持原身份。PC 在项目串行边界核对当前修订和摘要，保存决定时间、完整计划摘要及包含品牌契约的样式摘要。决定 ID 幂等，过期/冲突或损坏记录拒绝，不改动 PPT 页面、计划锁或生产输入。
- Project Store 用原子写入和内容校验保存最多 64 条决定；达到容量上限保留历史且不阻断普通制作。同一 ID 即使容量已满仍可读取原决定，不删除历史来腾出空间。
- PC 状态只返回有界决定元数据；损坏记录标为不可读，保留项目及计划。旧 PC 没有该能力时不展示接受按钮。
- 插件严格解析回执身份、文档、版本及两个摘要；刷新/重开只将与当前计划、样式完全匹配的决定标为当前已接受。修改计划后旧决定仅作为历史，即使样式未变也不自动批准新计划。
- 接受等待中、当前已接受或历史不可读时禁用按钮。取消、文档切换、迟到和摘要不匹配不采用错误决定；响应丢失时提示刷新，不自动重提。
- 时间线从真实持久决定生成 `plan.approved` 与 `style.approved`，保持决定身份及原时间，区分当前版本和历史。接受故事线/视觉方向不代表事实来源、视觉 QA 或真实宿主验收通过。
