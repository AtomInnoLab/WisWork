# 已完成只读结果的持久续跑

## 对照方案与实现

依据原方案 §7.2 和 AgentRun 恢复要求，已有“原请求安全重读”升级为完整文本工具批次的持久续跑。

- Core/Harness 增加续跑入口，验证调用/结果成对、身份一致、消息顺序和输入深度；从工具结果直接继续模型请求，不追加重复用户请求或重新执行旧工具。恢复时保留当前请求已使用轮次和重复调用限制。
- 下一次模型请求前等待批次保存。保存失败停止请求；等待时取消、重置或卸载，不会继续旧请求。停止后的已配对工具批次即使没有助手收尾消息，也能保留在后续上下文中。
- Office 在本机浏览器保存最多 128 条、128 KiB 的文本会话，整个本地记录最多 144 KiB，沿用七天 TTL；PPT 设置继续只存运行身份/阶段，不写请求或结果原文。任务结束清理本地记录，开始新的工具调用即清旧会话，防止复用同一调用 ID 时恢复旧结果。
- 恢复前后核对文档、运行和完整结果快照，沿用原 AgentRun 身份，不创建新的虚假执行记录。当前请求必须只使用已审计读取工具；以前已完成或停止的成对工具批次可作历史上下文，不重放。
- 插件入口实际接线，恢复按钮改为“恢复上次任务”。缓存结果明确标记历史观察，修改或声称当前状态前须重新核对；只读结果保存失败使用浏览器存储提示，不套用“PPT 可能已写入”的告警。
- Docs/Slides/Sheets/Markdown 的生命周期代理同步共享接口，不新增这些编辑器的恢复产品流程。
