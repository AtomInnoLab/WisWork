## 对应方案与完成内容

依据原方案 §4.3 Claim Ledger、O4，接通冻结页面主张到上传附件原始解析文本的只读链路。原方案不变。

- 新增 `read_presentation_claim_evidence` 插件工具及 `production_claim_evidence` PC 操作。请求必须给出项目、任务、页面、主张、来源、offset 和 max_chars。
- 服务读取指定生产任务的冻结计划，严格验证“页面包含主张、主张引用来源”；仅接受精确 `attachment:<sha256>` URI，使用同一文档下的附件读取。外部 URL/路径不访问。
- 返回主张、登记摘录、附件身份与原文窗口、输入/计划摘要及计划版本；后续改计划不会把历史任务偷偷换成新证据。
- 复用附件解析文本完整性校验、文档隔离和读取限额。单次最多 8000 UTF-16 code units，offset 上限 1000000，明确不等同 PDF 页码。
- 对登记摘录做逐字匹配，返回 found 的绝对文本偏移、not_found_in_window 或 empty_excerpt。跨窗口匹配需要调整读取范围，不归一化原文。
- 共享 parser 严格验证字段、范围、来源与附件身份、匹配结果及固定未核验状态；插件再验证请求绑定和实际返回窗口长度，沿用取消、清理和文档切换保护。
- 读取不编译、不改持久生产/QA/导入状态、不切换活动成果、不写 VFS 或最近项目；无需 PowerPoint 原生宿主执行。

报告始终明确 support/sourceAuthority/timeliness 未核验、host 未检查。摘录出现仅证明该解析文本窗口含有相同文字，不证明结论受支持、资料真实或现行有效。原文始终作为数据，不能当作 Agent 指令。
