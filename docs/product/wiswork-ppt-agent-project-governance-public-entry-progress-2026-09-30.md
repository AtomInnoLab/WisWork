# PPT Agent：本机项目治理入口阶段记录

日期：2026-09-30。依据原方案 §13.1、`docs/superpowers/plans/2026-09-29-ppt-project-deletion-executor.md` 与 `docs/superpowers/plans/2026-09-30-ppt-project-governance-entrypoints.md`。原方案文本不改。本记录区分代码接线、默认可用性、合成测试与真实使用。

## 本阶段交付

1. 七操作的独立 PC 适配器（`5c7be34f`）：预览、明确确认、原意图继续，控制记录初始化/读取、策略数字 CAS 与匿名审计导出。平面输入上限 32 KiB，控制/正文归属分离，内层模型最多 2 MiB，外层 JSON 包装最多额外 14 字节。初始化只接受实际 Store 项目绑定；控制只读允许项目正文已按原意图移除，不能授予新写入。确认/继续不登记为自己需要 drain 的 Work。
2. Office 浏览器合同、确认界面、持久原意图与只读恢复（`4d50e89e`）：同一当前文档及当前项目，预览后用户勾选确认；请求前保存原 scope/revision/token/deletionId。未知 ACK 或重新配对时先读取控制记录，只在 scope 与原随机 deletionId 匹配且状态仍为 deleting 时，允许用户显式继续，不自动重发或更换 ID。shared/unknown/partial 和项目正文保留均显示；默认策略 null/null，界面明确策略尚不自动清理。
3. 三端专有能力（`f0bf9452`、`d825ff8e`、`984010b8`、`1f513fb7`）：`presentation-governance.v1` 只在 PowerPoint 主连接，拒绝团队上下文与令牌、错误能力/操作族。三项新删除操作不能走旧能力；已发布的四项旧生命周期操作仍走原通道。PC 调用与普通项目操作共用实际项目锁；Office Runtime 只在真实绑定的主连接实际获得治理能力后启用。PC 可以登记完整 17 项已知能力目录，Office 一次请求仍最多 16 项，原 frame/输入预算不变。
4. 默认关闭的公开接线：本机 PC 只有 `WISWORK_PPT_PROJECT_GOVERNANCE_ENABLED=1` 才构造/提供治理 handler；Office 插件只有构建时 `VITE_WISWORK_PPT_PROJECT_GOVERNANCE_ENABLED=1` 才请求能力、建立控制器及显示删除界面。两侧默认均不启用。自动审批曾拒绝无门禁的直接公开入口，默认关闭的完整接线经自动审批允许；没有部署或打开生产开关。
5. 真实合成链路：Office 控制器通过实际 PC factory、项目 Store 与共用锁执行明确确认；模拟回执丢失后重开只读核对，保留同文档其它项目。七类独占命名空间清理、共享引用保留、持久失败重开与既有写入 guard 证据沿用前一阶段。所有验证只用合成临时目录，没有清理真实用户资料。
