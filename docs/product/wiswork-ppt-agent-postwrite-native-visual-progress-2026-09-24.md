# PPT Agent：现稿写后截图与视觉判断阶段小结

日期：2026-09-24。继续执行原方案 §6.4、O4/O5；原方案未修改。真实 PowerPoint 验收按用户要求暂缓。

## 本阶段完成

1. 确认提案在宿主写入和目标回读成功后，才运行可选的写后截图回调。截图失败会返回“证据不可用”，不会把已提交的修改误报成未写入。截图只证明当时采集到了页面，不自动记为视觉 QA 通过。
2. 现稿文字/几何、跨页批量修改、普通图片替换及整页重建都按准确的原生页 ID 采集写后 PNG。采集前后再次核对持久保存点和目标对象或整页包内容；整页暂存显示原页和新页，提交显示新页，放弃显示原页，撤销显示恢复页。批量修改逐页采集。
3. 确认结果向工作界面展示截图，向 Agent 返回受影响页 ID、截图摘要及“待视觉复核”状态。Agent 需要通过已有逐页截图工具逐页查看图片并给出判断，避免批量图片超过模型工具或请求体容量。历史视觉复核仍需明确记录；自动截图不会伪造通过结论。
4. 普通图片替换和整页重建增加逐页截图采集与 `pass/fail` 视觉判断工具。判断前重新读取宿主状态和截图；摘要、时间、原生页 ID 和备注持久写入同一个保存点。整页暂存时原页与新页分别记录；提交、放弃和撤销会清除先前状态的判断。工作台展示历史判断数量与逐页结果，并明确不等于当前页面 QA。
5. 写后截图成功后，把每个受影响页的 ID、PNG 摘要和采集时间作为有界回执持久写入保存点，不保存图片字节。截图失败时不写回执；整页暂存可一次记录两页。工作台据此逐页显示“待采集／已采集·待判断／通过／未通过”，后续提交、放弃或撤销会清除旧状态回执。
6. 保存点工作台的“检查”现会对图片替换及整页重建重新读取当前页面并截图，与历史回执摘要逐页比较。结果区分“一致／不同／暂无法核对”，遇到不同会提示重新复核；任何一致结果仍保持 `qaPassed: false`。整页暂存会分别比较原页与新页，不把其中一页的一致扩大成整批通过。

## 验证与边界

- Office Add-in 全量 **83 个测试文件、1333 项通过**；TypeScript 检查、生产构建及修改文件 ESLint 通过。新增测试覆盖历史视觉判断、写后截图回执、逐页记录、截图失败不写回执、状态变化时证据失效，以及按需重截图的一致与差异结果。
- 独立审查发现批量图片直接进入模型会超出 Agent 工具图片数与传输上限；现已改为界面展示图片、模型接收有界元数据，复核确认该问题解决。截图仍是会话证据，不在 Office 设置中保存图片字节。
- 现稿图片截图前后检查目标图片，不能证明同页其它形状未同时变化；整页路径会检查页序与页面包摘要。真实 PowerPoint 宿主、保存重开和 20 项专业任务验收仍 **0/20**，按用户要求暂缓。
- 截图二进制和 PowerPoint 宿主修订号没有持久化。由于 Office API 没有可靠的逐页修订号，本阶段用按需重截图比较作为等价当前画面检查；截图可能因宿主渲染差异而不同，因此“不一致”表示需要重审，不单独证明内容被修改。历史回执本身仍只证明当时采集成功。
